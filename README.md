<h1 align="center">polaris-agent</h1>

<p align="center">Host metrics and network probes for Uptime Polaris.</p>

<p align="center"><strong>English</strong> · <a href="#简体中文">简体中文</a></p>

Rust host agent for Uptime Polaris. The executable is `polaris-agent`, the daily management command is `pa`, and the Rust library is `polaris_agent`.

## English

### Scope



| Capability | Description |
| --- | --- |
| Host metrics | CPU, memory, disk, load, network and traffic measurements |
| Network probes | HTTP, TCP, TLS, DNS, domain expiry and Push-related checks |
| Connectivity | Continues sampling during disconnects and retries unacknowledged reports |
| Service management | `pa` manages status, logs, start, stop and restart operations |
| Remote operations | Optional configuration sync, re-report, update checks, restart and upgrade commands |

### Quick start

Use the installation command generated by the Uptime Polaris Agent page. After installation, check the service:

```sh
pa status
```

For a local build, run:

```sh
cargo build --locked --release
./target/release/polaris-agent --help
```

### Install

The installer queries the latest stable GitHub Release from the standalone repository, selects the detected operating system and architecture, and verifies the asset size and SHA-256 from `manifest.json`.


| Platform | Release asset |
| --- | --- |
| Linux x86_64 | `polaris-agent-0.1.0-linux-x86_64` |
| Linux aarch64 | `polaris-agent-0.1.0-linux-aarch64` |
| Windows x86_64 | `polaris-agent-0.1.0-windows-x86_64.exe` |
| macOS x86_64 | `polaris-agent-0.1.0-darwin-x86_64` |
| macOS aarch64 | `polaris-agent-0.1.0-darwin-aarch64` |

The installer registers both `pa` and `polaris-agent`; both commands manage the same executable and configuration.

### Build locally

Use a Rust toolchain that satisfies the `rust-version` in `Cargo.toml`. The binary is written to `target/release/`. Linux musl builds require the corresponding C toolchain, Windows builds require MSVC, and macOS builds require the matching SDK.

### Configuration

Configuration precedence is CLI arguments, then supported `POLARIS_AGENT_*` environment variables, then the JSON file. The installer manages metadata such as `service_tier` and `runtime_revision`; keep those fields.

| Field | Purpose | CLI or environment |
| --- | --- | --- |
| `endpoint` | Uptime Polaris origin or Agent endpoint; required | `--endpoint` / `POLARIS_AGENT_ENDPOINT` |
| `token` | Per-machine credential; required | `--token` / `POLARIS_AGENT_TOKEN` |
| `sample_interval` | Sampling interval, default 5 seconds | `--sample-interval` |
| `report_interval` | Reporting interval, default 60 seconds | `--report-interval` |
| `include_nics` / `exclude_nics` | Network-interface filters | Corresponding CLI arguments |
| `include_mounts` / `exclude_mounts` | Mount-point filters | Corresponding CLI arguments |
| `auto_update` | Check for updates after a successful report; disabled by default | `--auto-update=true` / `POLARIS_AGENT_AUTO_UPDATE` |
| `insecure` | Skip TLS verification for controlled diagnosis only | `--insecure=true` / `POLARIS_AGENT_INSECURE` |
| `log_file` | Optional log file | `--log-file` |

Sampling and reporting must satisfy `1 <= sample_interval <= report_interval <= 1800`. Unknown JSON fields are rejected. Do not enable `insecure` in production.

### Daily management

```sh
pa status
pa start
pa stop
pa restart
pa logs
pa logs -f
pa logs -n 200
```

Run in the foreground with `polaris-agent run --config /path/to/config.json`. Update or roll back with `pa update` and `pa rollback`. Automatic updates are disabled by default; Docker installations update by rebuilding the container.

### Remote configuration and security

Remote Agent commands are disabled by default. When enabled, configuration sync still enforces revisions, field limits and local CLI or environment overrides. Remote commands do not provide arbitrary shell execution.

Use a separate token for each machine. Do not commit installation commands, tokens or credential-bearing configuration, and do not place them in public logs or screenshots. Installers and the updater use the fixed GitHub Release repository; they do not fall back to static binaries hosted by the main site.

### Releases

The package version is defined in `Cargo.toml`. Push a stable tag matching that version, such as `v0.1.0`, to run `.github/workflows/release.yml`. The workflow builds five platform assets, creates `manifest.json` with the version, platform, size and SHA-256, and publishes a GitHub Release.

生产安装从 Uptime Polaris 控制台的 Agent 页面获取命令。安装器查询独立仓库的最新稳定 GitHub Release，并根据操作系统和架构下载匹配资产；安装过程会校验 Release 清单中的文件大小和 SHA-256。


| 平台 | Release 资产 |
| --- | --- |
| Linux x86_64 | `polaris-agent-0.1.0-linux-x86_64` |
| Linux aarch64 | `polaris-agent-0.1.0-linux-aarch64` |
| Windows x86_64 | `polaris-agent-0.1.0-windows-x86_64.exe` |
| macOS x86_64 | `polaris-agent-0.1.0-darwin-x86_64` |
| macOS aarch64 | `polaris-agent-0.1.0-darwin-aarch64` |

安装完成后运行：

```sh
pa status
```

回到控制台确认机器首次上报。安装脚本同时注册 `pa` 和 `polaris-agent`，两个命令管理同一份程序和配置。

### 本地构建

要求 Rust 工具链满足 `Cargo.toml` 中的 `rust-version`。在本目录执行：

```sh
cargo build --locked --release
```

构建产物位于 `target/release/`。运行帮助命令：

```sh
./target/release/polaris-agent --help
```

Linux musl 构建需要对应的 C 工具链；Windows 构建需要 MSVC；macOS 构建需要对应 SDK。

### 配置

配置优先级为：命令行参数 > `POLARIS_AGENT_*` 环境变量 > JSON 配置文件。安装器会维护 `service_tier` 和 `runtime_revision` 等元数据，不要手工删除这些字段。

```json
{
  "endpoint": "https://status.example.com",
  "token": "replace-with-machine-token",
  "sample_interval": 5,
  "report_interval": 60,
  "include_nics": [],
  "exclude_nics": ["lo"],
  "include_mounts": [],
  "exclude_mounts": [],
  "auto_update": false,
  "insecure": false
}
```

| 字段 | 用途 | CLI 或环境变量 |
| --- | --- | --- |
| `endpoint` | Uptime Polaris 站点或 Agent 端点，必填 | `--endpoint` / `POLARIS_AGENT_ENDPOINT` |
| `token` | 当前机器的身份凭据，必填 | `--token` / `POLARIS_AGENT_TOKEN` |
| `sample_interval` | 采样间隔，默认 5 秒 | `--sample-interval` |
| `report_interval` | 上报间隔，默认 60 秒 | `--report-interval` |
| `include_nics` / `exclude_nics` | 网卡过滤列表 | 对应 CLI 参数 |
| `include_mounts` / `exclude_mounts` | 挂载点过滤列表 | 对应 CLI 参数 |
| `auto_update` | 成功上报后检查更新，默认关闭 | `--auto-update=true` / `POLARIS_AGENT_AUTO_UPDATE` |
| `insecure` | 跳过 TLS 证书校验，仅供受控排查 | `--insecure=true` / `POLARIS_AGENT_INSECURE` |
| `log_file` | 可选日志文件路径 | `--log-file` |

采样和上报必须满足 `1 <= sample_interval <= report_interval <= 1800`。未知 JSON 字段会被拒绝。`insecure` 不应在生产环境启用。

### 远程配置与安全

后台默认关闭远程 Agent 指令。启用后，配置同步仍受版本号、字段限制和本地 CLI／环境变量覆盖约束。远程指令不提供任意 Shell 执行能力。

每台机器使用独立 Token。不要把安装命令、Token 或包含凭据的配置提交到代码仓库、公开日志或截图。GitHub Release 清单和下载地址由项目固定配置指定；安装器和更新器不会回退到主站静态二进制。

### 发布

版本位于 `Cargo.toml`。推送与版本一致的稳定 Tag（例如 `v0.1.0`）后，`.github/workflows/release.yml` 会构建五个平台资产，生成包含版本、平台、大小和 SHA-256 的 `manifest.json`，并创建正式 GitHub Release。

发布配置位于 `release-repository.json`：

```json

}
```

不要在发布工作流中使用未经验证的仓库名、下载地址或手工生成的清单。
